# Generic CRM UI Example

This standalone project is a temporary, runnable CRM workload for viewing Favn
assets, lineage, windows, freshness, checks, and run states in the local UI.

It uses four layers:

1. **Landing** — compact deterministic JSON in `.data/generic_crm/landing/`.
2. **Source** — DuckDB tables loaded from those JSON files.
3. **Core** — CRM-vendor-neutral customer, opportunity, and activity models.
4. **Mart** — account health, daily pipeline, and an executive overview.

The implementation intentionally demonstrates both full refresh and daily
windowed work. See the temporary design note at
`docs/refactor/generic-crm-example.md` for the feature-to-asset mapping.

## Run the example

From this directory:

```powershell
mix deps.get
mix compile
mix test
```

For the local UI loop, provide PostgreSQL through the normal Favn environment,
then run:

```powershell
$env:FAVN_RUNTIME_INPUT_PIN_KEY = '01234567890123456789012345678901'
$env:FAVN_DATABASE_URL = 'ecto://favn_migrator:favn_migrator_local@127.0.0.1:5432/favn_dev'
mix favn.postgres.migrate
mix favn.postgres.grant_runtime --role favn_runtime
mix favn.postgres.provision_workspace --id local-dev --slug local-dev --name 'Local Development'

$env:FAVN_DATABASE_URL = 'ecto://favn_runtime:favn_runtime_local@127.0.0.1:5432/favn_dev'
mix favn.dev
mix favn.run FavnReferenceWorkload.Pipelines.BootstrapCrmDemo
```

The first pipeline target to run manually is
`FavnReferenceWorkload.Warehouse.Mart.AccountHealth`, which exercises the full
refresh path. The daily pipeline is
`FavnReferenceWorkload.Pipelines.DailyCrmAnalytics` and requires a daily
window. Use the UI run controls or the documented
`mix favn.run --window` form to select `2026-07-23` while inspecting the example.

After a run, inspect the graph and run detail pages for:

- Landing multiasset children and their metadata;
- Source → Core → Mart dependency edges;
- full-refresh versus daily-window execution;
- freshness and coverage state;
- the `Mart.AccountHealth` candidate check; and
- `Mart.ExecutiveOverview` as the UI-facing output.

The data plane is `generic_crm.duckdb`. The landing files are disposable
local demo state and can be regenerated by running the Landing assets again.
Set `DUCKDB_ADBC_DRIVER` to a compatible DuckDB library before starting Favn;
on Windows, this is normally the absolute path to `duckdb.dll`.
